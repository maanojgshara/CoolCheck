# Dataset register

One row per dataset or feed that CoolCheck uses, holds or plans to use (H15, D11). It is the source for every dataset count in the write-up and the deck. Built 22 Oct 2026 from `coolcheck-data/static/SOURCES.md`, each `provenance.json`, the backfill and collector code, the geocoding write-up, the EMA workbooks and the terms saved in `../Docs/`. Statuses describe the repository as it is today; roles marked (proposed) wait for a Day 4 decision.

**Unit of count:** one data.gov.sg dataset ID, one API feed, or one file release from another source. The two EMA workbooks are one release, so one row. Licence abbreviations: ODL = Singapore Open Data Licence v1.0 (`https://data.gov.sg/open-data-licence`).

## Licence flags

My reading of the saved terms, not legal advice. The same ODL conditions apply to every row: no suggestion of official status or agency endorsement (so the agent's advisories must say they are not official advice), no rights over personal data (none is used), the notice above, and a licence that an agency may end on breach.

**A. EMA (row 22).** Terms file: `../Docs/EMA/EMA _ Terms of Use.pdf`, section "Terms of Use of Datasets". It is the ODL v1.0 in EMA's own words (clause 20: "This is version 1.0 of the Singapore Open Data Licence"): use, copy, adapt, commercial or not (3); clause 7, no suggestion of EMA endorsement; clause 9, the same notice as above with a link to the licence. Open point: the same PDF's website terms (clause 6) say no part of the website may be reused for commercial purposes without EMA's written permission. I read the dataset section as governing the SES workbooks, which are datasets, but the page does not say that in so many words. A hackathon use is non-commercial, so the point matters only if CoolCheck goes beyond it. Also: the EMA site blocks scripts (Incapsula), so the workbooks were downloaded by hand and cannot be refreshed by code.

**B. SingStat (rows 6, 7, 8).** Terms file: `../Docs/SingStat - terms of use.pdf`. Clause 10 grants copying, distribution and derived products, free, if you credit the source (10c), do not suggest the Government or a statutory board is behind your analysis (10e) or endorses you (10h), keep reproductions accurate (10g), and stop using the Contents and remove them if SingStat asks (10f). Clause 11 puts datasets under the ODL and says the ODL prevails where the two differ. **Clause 25 requires written permission before hyperlinking to any SingStat page or content.** So in public material (the deck, the app, a public repository) name the June 2026 file by title and date and do not link to singstat.gov.sg; this register therefore leaves that link out (it is in `SOURCES.md` and `provenance.json`, which should stay out of any public copy). Rows 6 and 8 come through data.gov.sg and link to data.gov.sg, not SingStat. `provenance.json` and `SOURCES.md` for row 7 still say "Not confirmed" for the licence; they predate the 21 Oct reading of clause 11 and are stale. The counts are rounded to the nearest 10, so figures must not be presented as exact (10g).

**C. OneMap (row 23).** Terms file: `../Docs/OneMap/OneMap _ API Terms of Service.pdf` (re-read 22 Oct). Use of the datasets is under the ODL; the API service is under the API terms. Allowed: query the API commercially or not. Required: use the credentials issued to you and keep them secure and confidential (the token is read from `ONEMAP_TOKEN` only and never printed); do not mask the client's identity; do not interfere with the service. The agency may monitor use, may suspend or end access for any reason, and may change the API at any time, so the geocodes should be treated as a one-off pull held in `geocode/`, not a service the product depends on. The terms have no attribution clause of their own, but they say dataset use is under the ODL, so the notice in row 23 is offered to be safe. OneMap's own page, as you reported it on 22 Oct, gives 300 calls a minute and a 3-day token for Search (I did not see that page). The saved per-API pages in `../Docs/OneMap/` carry no rate limit for the search API (only the MCP gateway page gives one, 5 requests a second, which this project does not use); I did not read them line by line for other terms.

**D. Meteorological Service Singapore (row 5).** No terms file in `../Docs/`: **terms not read** from a saved file. The clauses in `docs/checks/check6.md` come from a script's fetch of the live terms page on 21 Oct and were not re-read today. Per that write-up there is no open-data licence on the page; reproducing or republishing needs prior written permission (4.1); use is limited to personal, internal, non-commercial or informational purposes (4.3); and a robot or other automatic device needs permission (6.2). Nothing has been fetched. The fallback is NEA's data.gov.sg air-temperature history (row 4, `date=`), which is under the ODL.

**E. data.gov.sg real-time APIs (rows 1 to 4, 8) and the other data.gov.sg rows.** The saved file `../Docs/data.gov.sg - Open data licence.pdf` is the dataset licence. No API terms of service for the real-time endpoints are saved in `../Docs/`: **API terms not read**. The rate limits used (6 calls per 10 seconds without a key, 12 with a Developer key) come from the Guide and the Brief, and the key is sent as `x-api-key` from the environment only. Dataset pages were opened only for rows 12, 16, 17 and 20 (plus a search snippet for row 11), so for the other data.gov.sg rows the ODL is the platform licence and not a licence read on the dataset page (shown in the licence column). Row 21 (LTA) was inspected before the licence column was filled and its dataset page was not opened.
